# 好感度（关系）系统设计 —— 阶段 1

> 代码：`src/affinity.js`（纯函数引擎）、`src/bridge.js`（记账 + 提示词注入 + 接口）
> 单测：`node scripts/test-affinity.mjs`（33 条断言）
> 状态：`state/social-v2.json` → `conversations[<key>].affinity.members[<QQ号>]`

## 0. 一句话定位

**对群友完全隐藏**：不提供查询、不做排行榜，只通过「怎么称呼他 + 说话的温度」体现出来。
阶段 1 **不动**生图配额、**不动**唤醒优先级。

---

## 1. 分档表（起始 40，量程 −200 ~ 1000）

> 2026-09-27 按 owner 要求改成**宽量程**：分档阈值拉高，配合"每天最多 ±6"的细则，
> 涨得慢、也难得掉到底。原写法里 `有点烦 -50~-1` 与 `梁子 -50-` 在 **−50** 上重叠，
> 这里按"越负越差"处理：**−50 及以下 = 梁子，−49 ~ −1 = 有点烦**。

| 分数 | 档位 | 语气档 | 称呼规则 | 语气要求（注入给模型） |
|---|---|---|---|---|
| 300 ~ 1000 | 自己人 | 0 | 可叫名字/外号 | 亲昵、互损、主动找他说话；可以起外号、拿他开玩笑，被怼了可以怼回去 |
| 100 ~ 299 | 熟人 | 1 | 可叫名字/外号 | 随意、爱开玩笑、愿意接话和帮忙；可以直接叫名字 |
| 40 ~ 99 | **普通群友（起始值 40 落这里）** | 2 | 群名片全称 | 正常聊天，不冷不热；不主动献殷勤，也不故意冷落 |
| 0 ~ 39 | 眼熟 | 3 | 群名片全称 | 客气、简短；不主动找他搭话，问他事就正常答 |
| −49 ~ −1 | 有点烦 | 4 | 群名片全称 | 敷衍、少接话（可以已读乱回、装没看见）；但不骂人、不人身攻击 |
| ≤ −50 | 梁子 | 5 | 不叫称呼（"那位"） | 冷淡、能推就推；最多阴阳一句，绝不说难听话、不主动攻击 |

**爬到各档要多久**（按每日净涨上限 +6 估算，实际多数人 2~4 分/天）：

| 目标 | 最少天数 | 实际体感 |
|---|---|---|
| 普通群友（起始就是） | 0 天 | — |
| 眼熟（0~39） | 掉下来才见得到 | 只有衰减或扣分才会回到这档 |
| 熟人 100 | **10 天**（满勤） | 约 3~5 周 |
| 自己人 300 | **44 天**（满勤） | 约 2~4 个月 |

设计取舍：
- **起始值必须落在最中性的"普通群友"**，否则新人一进来就是"客气/冷淡"语气（开发中踩过一次边界，已修）。
- **新人在面板里不出现**（面板只列近 15 分钟说过话的人），人设规定"面板里没有的人按普通群友处理"。
- 如果觉得"自己人"太遥远，把 `dailyUp` 调到 10~12，或把 300 降到 200（改 `tierOf()` 一行）。

## 2. 计分规则（全部确定性，不用模型打分）

| 事件 | 分值 | 每日计分上限 | 判定细节 |
|---|---|---|---|
| 当天首次冒泡 | **+2** | 每天一次 | 跨天重置；同一天再聊多少条都不再给这个分 |
| @ 机器人 / 引用机器人消息 | **+1** | 4 次 | 消息段里有 `at` 指向机器人，或 `reply` 指向机器人 |
| 发图片（不含表情包） | **+1** | 2 次 | 消息里带 image 段 |
| 踩雷点词 | **−2** | 2 次 | 默认词表：`大肥鱼、肥鱼、死鱼、傻鱼、蠢鱼、蓝色胖子、蓝胖子` |
| 刷屏 / 复读 | **−2** | 2 次 | 该人 60 秒内 ≥6 条，**且**（重复内容 ≥3 条 **或** 平均长度 ≤6 字） |
| 普通聊天（当天非首次） | 0 | — | 故意不给分：否则话多的人白拿分 |

**为什么"话多"不加分**：这个系统要衡量"关系"，不是"发言量"。发言量只会让刷屏的人占便宜。

---

## 3. 封顶、衰减与边界

| 机制 | 数值 | 说明 |
|---|---|---|
| 每日净涨跌封顶 | **+6 / −6** | 超出部分只记事件、不进分数（防一天刷满） |
| 闲置衰减 | 闲置 >7 天后 **每天 −1** | 懒衰减，在"记账时/注入面板时"结算 |
| 衰减下限 | **20** | 只掉到"眼熟"，**不会**因为不说话被打成"有点烦/梁子" |
| 分数范围 | −200 ~ 1000 | 读写都做夹紧；脏数据在加载时清洗 |
| 私聊 | 不统计 | 阶段 1 只算群聊 |
| 事件日志 | 保留最近 20 条 | 每条记 `时间/类型/本次变化/原因`，便于回溯"这分怎么来的" |

## 4. 两个推演示例

**示例 A：正常新人第一天**（起始 40）
```
早上冒泡一句            +2 → 42
@ 机器人问了个问题       +1 → 43
发了张图                +1 → 44
又 @ 了两次             +2 → 46
当天其余聊天            +0 → 46   （日封顶未触及）
第二天再冒泡            +2 → 48
```
→ 一周内自然爬到 50~58（普通群友中段），要进"熟人"（100）得持续互动 3~5 周。

**示例 B：复读机的一天**
```
首条 "ojj"              +2 → 42
60 秒内刷 8 条同内容     −2 → 40（第 1 次刷屏）
继续刷                  −2 → 38（第 2 次刷屏，已达上限）
踩一次雷点词            −2 → 36
当天其余行为一律 0
```
→ 一天最多掉 6 分（日封顶），不会一夜之间被打成"梁子"；要真到梁子（≤−50）得长期如此
（从 40 掉到 −50 需要 15 天满勤扣分）。

## 5. 调参位置

`config.json` → `socialV2.affinity`（都可以不写，用下面的默认值）：

| 键 | 默认 | 作用 |
|---|---|---|
| `enabled` | true | 总开关（关掉则不计分、不注入面板） |
| `start` / `min` / `max` | 40 / −200 / 1000 | 初始分与量程 |
| `dailyUp` / `dailyDown` | 6 / 6 | 每日净涨跌封顶 |
| `decayAfterDays` / `decayTo` / `decayPerDay` | 7 / 20 / 1 | 衰减节奏与下限 |
| `caps.attention` / `caps.share` / `caps.rude` / `caps.spam` | 4 / 2 / 2 / 2 | 各类事件每日计分上限 |
| `rudeKeywords` | 见上表 | 雷点词表（可增删） |
| `spamWindowMs` / `spamCount` / `spamRepeat` / `spamShortChars` | 60000 / 6 / 3 / 6 | 刷屏判定 |

分档阈值在 `src/affinity.js` 的 `tierOf()`，语气文案在 `TONE_RULES`。

## 6. 运维入口

```bash
node scripts/affinity-admin.mjs list                      # 看全表（含今日涨跌/闲置时长/最近事件）
node scripts/affinity-admin.mjs set <QQ> "<名字>" <分数>   # 手调某人分数
node scripts/affinity-admin.mjs remove <QQ>               # 删掉某人
```

HTTP：`GET /api/socialV2/affinity?key=group:541234567`、`POST /api/socialV2/affinity`

> ⚠️ **别用 PowerShell 的 `Invoke-RestMethod` 发中文**：PS 5.1 的 `-Body` 字符串默认不走 UTF-8，
> 中文名字会被写成 `?? ??`（实测踩过）。用上面的 Node 脚本。

排查看日志：`state/bridge.log` 里的 `[affinity] 某某 +2 → 42（今天首次互动+2）`。

## 7. 阶段 1 不做什么

- ❌ 生图配额随关系浮动（现在固定 5 次/天）
- ❌ 唤醒优先级 / 回复优先级按关系排序
- ❌ 主动搭话挑熟人、外号记忆、"人情账"
- ❌ 群友查询自己的分数、任何排行榜

（这些是阶段 2~4 的候选，等阶段 1 的分数曲线看起来合理、且没出现跑偏再上。）

## 8. 已知边界与风险

1. **雷点词是纯字符串匹配**：可能误伤（例如群友正常讨论"鲸鱼"没事，但有人名字里带"肥鱼"就会一直扣分）。发现误伤就删词或降低权重。
2. **刷屏判定偏保守**（60 秒 ≥6 条 + 重复/极短）：热闹刷梗时可能误判。若误判多，把 `spamCount` 提到 8。
3. **名字靠群名片**：QQ 名片改名后，桥接只在有消息时更新名字。
4. **模型可能说漏嘴**：面板里写了"绝不能说出口"、人设 30.2 也禁止，但仍需观察；若发现它暗示分数，就把面板里的"档位名"也去掉，只留"语气档 N"。
5. **好感度天然带情绪风险**：低档只允许"冷淡/敷衍/拒绝服务"，明令禁止人身攻击；若群里出现因此闹矛盾，直接 `enabled: false` 一键关停。
